Five-session plan

1

Graph semantics

Define shapes, dtypes, broadcasting, side effects, dynamic dimensions, and numerical tolerance.

2

Canonicalization and fusion

Apply shape inference, constant folding, dead-code elimination, and legal fusion with before/after checks.

3

Target legalization

Mark supported operations and lower unsupported graph structure without losing layout information too early.

4

Bufferization and scheduling

Make allocation, lifetime, tiling, DMA, synchronization, and core placement explicit.

5

Verify the pipeline

Run semantic checks after every pass and preserve a minimized failing IR case.

Lowering pipeline and verification gates

  1. Framework graphFreeze shape, dtype, broadcasting, side effects, and reference outputs.
  2. Canonical tensor IRFold and fuse only when graph semantics remain equivalent.
  3. Target-legal tiled IRChoose supported operations, layouts, tile shapes, and tail behavior.
  4. Bufferized scheduleExpose allocations, lifetimes, DMA, core placement, and synchronization.
  5. Runtime commandsExecute and compare normal, boundary, and unsupported cases with the reference.

End-to-end artifact: miniature lowering pipeline

Start with relu(matmul(x, w) + bias). Publish four readable IR snapshots: graph, fused tensor IR, tiled/bufferized IR, and runtime command sequence. Each pass must state legality, preserved invariants, expected benefit, and a counterexample where it must not apply.

Validated when: reference and lowered outputs agree within a declared tolerance for normal, boundary, and deliberately unsupported shapes.
