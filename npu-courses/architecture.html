NPU course 1

Accelerator architecture and memory movement

Learn hardware through one question: how do tensor tiles move, fit, synchronize, and get reused?

Course mapPlanArtifactReference

Four-session plan

1 · Contract

Work and data

Calculate shapes, MACs, bytes, arithmetic intensity, and layout for one GEMM. Gate: all dimensions and units are explicit.

2 · Hierarchy

Memory movement

Map DRAM, interconnect, local SRAM, circular buffers, registers, and accumulators. Gate: every transfer names source, destination, bytes, and synchronization.

3 · Mapping

Tiling and core grid

Select M/N/K tiles, shard them across a core grid, and check capacity plus tail behavior. Gate: no buffer exceeds its declared capacity.

4 · Measure

Bottleneck prediction

Predict compute- or bandwidth-bound behavior, then compare with a measured or modeled result. Gate: discrepancy is explained rather than hidden.

Tile movement and reuse

  1. DRAM tensorsSelect M×K and K×N tiles; count source bytes.
  2. DMA and interconnectMove tiles to the owning core with an explicit synchronization event.
  3. Local circular buffersDouble-buffer tiles and prove the working set fits SRAM.
  4. Matrix engineReuse operands across MACs while partial sums remain local.
  5. WritebackStore the output tile and compare measured behavior with the bottleneck prediction.

End-to-end artifact: tiled GEMM mapping report

  1. Choose a realistic M×K by K×N workload.
  2. Produce a tensor/layout table and memory-capacity worksheet.
  3. Draw the double-buffered dataflow over a core grid.
  4. Estimate bytes, MACs, reuse, and limiting resource.
  5. Change one tile dimension and explain the predicted tradeoff.

Validated when: a reviewer can reproduce every number and identify which hardware constraint selects the mapping.
