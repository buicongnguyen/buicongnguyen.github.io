Quantization, runtime, and deployment

Turn one model into a versioned artifact with accuracy, fallback, latency, throughput, and memory evidence.

Four-session plan

1

Export contract

Freeze preprocessing, shapes, dtypes, output semantics, dynamic axes, and framework baseline.

2

Calibration and quantization

Choose representative calibration data, inspect sensitive tensors, and compare FP32 with INT8 per output and task metric.

3

Partition and fallback

Record supported operators, graph partitions, copies, fallback cost, and failure behavior for unsupported shapes.

4

Benchmark and release

Separate cold start from steady state; report latency percentiles, throughput, memory, power context, versions, and sample count.

Deployment evidence flow

  1. Framework FP32Freeze preprocessing, inputs, outputs, and reference metrics.
  2. Exported graphCheck graph structure and FP32 runtime parity.
  3. INT8 calibrationUse representative training-only data and record scales.
  4. NPU/CPU partitionExpose unsupported operators, copies, and fallback boundaries.
  5. Runtime measurementSeparate cold start, steady-state latency, throughput, and memory.
  6. Release packetBind model, compiler, runtime, device, accuracy, and performance evidence.

End-to-end artifact: deployment evidence packet

  1. Export a small classifier or encoder.
  2. Validate framework/runtime FP32 parity.
  3. Calibrate INT8 on a training-only representative split.
  4. Evaluate untouched accuracy and per-output error.
  5. Record partition/fallback and benchmark cold plus steady-state execution.

Validated when: one command regenerates the report and the conclusion distinguishes model quality, compiler coverage, transfer overhead, and device execution.
