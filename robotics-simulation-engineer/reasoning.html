The rule behind every diagram

  1. Name the expected invariant.
  2. Find the first boundary where it fails.
  3. Explain a mechanism that predicts a unique signal.
  4. Run the smallest experiment that could prove you wrong.
  5. Turn the result into a regression and a bounded claim.

A strong engineer does not begin with a favorite tuning knob.

Five questions at every boundary

Use the same mental model from configuration to ROS and CI

If one answer is missing, the boundary is not yet debuggable.

OwnerWho writes this value?

One source of truth, one lifecycle phase, explicit override precedence.

ContractWhat must be true?

Type, shape, unit, frame, rate, range, ordering, timeout, and failure behavior.

StateWhen is it valid?

Before Play, after reset, pre-step, post-step, after sensor acquisition, or terminal.

EvidenceWhat would reveal failure?

First bad sample, requested/applied pair, source timestamp, raw contact, or resource trace.

DecisionWhat changes my mind?

A predicted signature, restoration, counter-example, and precommitted pass criterion.

Isaac Sim 6.0 standalone code lifecycle

Initialization order is part of correctness

This sequence matches the installed C:\isaacsim 6.0 RC pattern. Parse ordinary Python arguments first, create SimulationApp, and only then import APIs supplied by the running Kit application. Mark version-sensitive code and never mix 4.x/5.x snippets into a 6.0 project without an API check. 

# Isaac Sim 6.0 project skeleton — helper functions are project hooks.
from enum import Enum, auto
from time import perf_counter
from isaacsim import SimulationApp        # runtime boundary

app = SimulationApp({"headless": args.headless})

# Import Kit/Isaac APIs only after the app exists.
from isaacsim.core.api import World

class Phase(Enum):
    APP_READY = auto(); STAGE_READY = auto(); RESETTING = auto()
    READY = auto(); RUNNING = auto(); TERMINAL = auto()
    FLUSHING = auto(); FAULT = auto()

phase, writer = Phase.APP_READY, None
try:
    cfg = load_and_validate_config(args.config)
    identity = capture_identity(cfg, args.seed)
    writer = open_bundle(identity)

    world = World(
        stage_units_in_meters=1.0,
        physics_dt=cfg.physics_dt,
        rendering_dt=cfg.render_dt,
    )
    handles = build_and_audit_scene(world, cfg)
    phase = Phase.STAGE_READY

    for episode in range(cfg.episodes):
        phase = Phase.RESETTING
        reset_all_owners(handles, cfg, args.seed, episode)
        world.reset()                       # initialization barrier
        reset_snapshot = assert_reset_contract(handles)
        writer.write_reset(reset_snapshot)
        phase = Phase.READY

        requested = applied = None
        wall_start = perf_counter()
        phase = Phase.RUNNING

        for step in range(cfg.max_steps):
            state_k = read_control_state(handles)
            if step % cfg.control_decimation == 0:
                requested = controller(state_k)
                applied = actuator_contract(requested, state_k)
                apply_action(handles.robot, applied)

            writer.write_pre_step(step, requested, applied)
            world.step(render=should_render(step, cfg))

            state_next = read_physics_state(handles)
            contacts = read_raw_contacts(handles)
            sensors = acquire_due_sensors(handles)
            assert_step_contract(step, state_next, sensors)
            result = evaluator(state_next, contacts, sensors)
            writer.write_post_step(step, state_next, contacts, sensors, result)

            if result.terminal:
                phase = Phase.TERMINAL
                break

        writer.finish_episode(episode, result, perf_counter() - wall_start)
        phase = Phase.FLUSHING
except Exception as error:
    phase = Phase.FAULT
    if writer:
        writer.write_fault(error, capture_first_bad_context())
    raise
finally:
    if writer:
        writer.close()
    app.close()

Project-hook rule: functions such as build_and_audit_scene, actuator_contract, and assert_step_contract are intentionally yours. Their job is to make ownership and failure behavior explicit; do not hide these contracts inside a monolithic loop.

Data lineage and provenance

Every published claim must trace backward to immutable inputs

Do not collapse these pairs

  • Declared parameter versus sampled realization
  • Requested target versus applied action
  • Physics truth versus sensor output
  • Acquisition time versus publish/receipt time
  • Reward versus independent physical success

Calibration and randomization flow

  • Fit split + reference traces → M7 identifier
  • Identifier → versioned parameter manifest
  • Manifest + justified residual uncertainty → M8 distribution
  • Distribution → recorded sampled parameters
  • Nominal and held-out results remain separate

Time, rates, and sensor cadence in Isaac Sim 6.0

“60 Hz” is meaningless until you name the clock and event

PhysicsState-transition cadence

physics_dt, substeps, solver work, and simulated time advanced per physics step.

TimelinePlayback time

Timeline tick and time-code behavior; pause/stop/reset policy must be declared.

App/renderUpdate cadence

On Playback Tick and rendering can be limited by workload and need not equal physics cadence.

SensorAcquisition cadence

RTX sensors use the sensor prim’s omni:sensor:tickRate; production cost can still miss wall-rate targets.

ROS/wallTransport and capacity

/clock carries simulation time; ros2 topic hz observes wall-time arrival frequency.

Choose the event intentionally

  • On Physics Step: align a graph action with each physics transition.
  • On Playback Tick: align with each application/render playback update.
  • Sensor tick: acquire only when that sensor is due.
  • Control decimation: update control every N physics steps while holding the applied action.

Record the complete timing tuple

  • Physics step ID and simulation time
  • Sensor acquisition/source timestamp
  • ROS header and TF timestamp
  • Publish and consumer receipt wall times
  • Expected cadence, observed cadence, latency, jitter, and dropped/held policy
Current 6.0 update: for RTX sensors, prefer the sensor prim’s omni:sensor:tickRate. A nonzero legacy frameSkipCount is deprecated and can interact badly with the sensor tick. Use the measurement’s source simulation time—not an unrelated wall or current timeline read—as its timestamp. Publish /clock, set downstream use_sim_time=true, and look up TF at the message stamp.
Installed-RC caution: current NVIDIA 6.0 documentation describes a full-UI crash when changing physics/timeline rates away from the default and then playing. Test rate changes in a minimal standalone reproduction against 6.0.0-rc.59 before adopting a stable-6.0.1 example.

Causal-proof decision logic

Symptom removal is not proof of root cause

Prediction, restoration, and counter-testing distinguish a real explanation from a coincidental improvement.

Gate 1 · reproduceDid the fixed-identity baseline reproduce?Same commit, runtime, hardware, config/assets, seed, x₀, and action trace.
Improve identityCapture a bounded reproduction bundle.
Gate 2 · locateCan you name the first failed invariant and boundary?Not the final visible symptom—the first incorrect output after a valid input.
Improve observabilityAdd instrumentation at the adjacent boundaries.
Gate 3 · predictDoes the hypothesis predict a unique measurable signature?State what should change and what should stay unchanged.
Refine hypothesisSplit broad explanations into falsifiable causes.
Gate 4 · interveneDid one variable move the predicted signal?Hold the resolved manifest and workload fixed.
FalsifiedTest the next ranked cause.
Gate 5 · restoreDid restoring the baseline bring the failure back?Repeat enough times to expose intermittent behavior.
ConfoundedInvestigate nondeterminism or an uncontrolled change.
Gate 6 · counter-testDid a predicted unaffected case remain unchanged?This tests whether the intervention is specific to the proposed mechanism.
Non-specificThe intervention is broad; narrow the claim.
Gate 7 · landDoes the fix pass nominal, held-out, safety, and performance gates?Retain failing-then-passing regression evidence and known limitations.
Incomplete fixMeasure the trade-off or redesign.

Worked reasoning examples

Follow the evidence chain, not the tempting shortcut

Failure A · Robot explodes on the first physics step
ObservationState is finite before reset; extreme velocity or NaN appears on the first physics step before a meaningful command.
ContractRESETTING must finish with finite in-limit state, declared velocity, separated colliders, valid inertia, and controller disabled.
HypothesesReset penetration/stale velocity; bad scale/inertia/joint; duplicate command owner; dt/mass-ratio instability.
Discriminating testCapture x₀/separation/action. Step once controller-free and gravity-off; restore gravity, contact, then controller independently.
DecisionStable without contact but explosive with contact points to reset overlap/collider—not gains. Change only to a validated separated pose.
Regression100 reset/one-step cycles assert finite state, velocity, separation, first impulse, resources; a planted overlap must fail.
Failure B · Sensor is plausible internally but stale and rotated in ROS
ObservationInternal sample matches the scene; subscriber view lags and a known target is rotated after TF.
ContractSame sample identity, source simulation stamp, frame/extrinsic, compatible QoS, and TF lookup at that exact stamp.
HypothesesMixed sim/wall time; optical/body frame error; TF lookup at wrong stamp; QoS backlog; acquisition/publish cadence mismatch.
Discriminating testJoin internal → publisher → subscriber by sequence/hash. Log acquisition, header, receipt, frame, and Tworld,sensor at stamp.
DecisionFix only time first. If lag disappears but rotation remains, these are two faults; then change only optical extrinsic/frame.
RegressionMonotonic stamps, bounded age, expected cadence, exact-stamp TF, known-axis check, pause/reset/replay cases.
Failure C · Cameras make the run slow and the same seed diverges
ObservationPhysics-only is fast; cameras reduce real-time factor, add p95 spikes, and same-seed trajectories diverge.
ContractControl cadence is physics-owned; sensors are timestamped and consumed by policy; workload and warm-up are fixed.
HypothesesControl tied to render cadence; RTX/readback sync; blocking logging; resource accumulation; warm-up; GPU scheduling.
Discriminating testFrozen matrix: physics → controller → render → one camera → all sensors → ROS/logging. Record RTF, p50/p95, memory, hashes.
DecisionIf first divergence appears only with render, move control to physics cadence and use explicit timestamped sensor hold/drop policy.
RegressionHardware/version-stamped scaling matrix, RTF/p95 budgets, bounded memory, correctness, and same-hardware hash/tolerance.

Reasoning practice

Answer “why” before revealing the path

Why must SimulationApp exist before most Isaac/Omniverse imports in standalone code?

The APIs are supplied by the running Kit extension/plugin system. Creating the app establishes that runtime. The engineering consequence is that import order becomes a startup contract: ordinary CLI parsing can precede it, but runtime-dependent imports follow it.

Why is reset a barrier rather than “just set the poses”?

Reset coordinates every stateful owner: physics/views, pose and velocity, controller memory, sensor buffers, task counters, sampled parameters, and time policy. Control or sensing before the barrier can consume stale or invalid state, so readiness must be asserted explicitly.

Why log requested and applied actions separately?

Delay, rate limits, saturation, actuator/drive semantics, safety state, and watchdogs can change the physical command. Motion responds to the applied action. Without both values, controller error can be confused with actuator or safety behavior.

Why inspect raw contact before tuning friction?

Collider geometry, initial penetration, mass/inertia, contact/rest offsets, dt, and solver resolution decide whether and how constraints form. A filtered sensor can also hide raw contacts through thresholds. Friction tuning around a geometry or timing defect hides the cause.

Why is a seed not a complete reproduction identity?

The sampled sequence also depends on code/config/assets, RNG owners/order, runtime/physics version, hardware, initialization order, and action trace. GPU scheduling and floating-point order can diverge across environments. Record the realized parameters and x₀, not only the seed.

Why can a ROS topic be discovered but still deliver no useful samples?

Discovery only proves DDS participants see endpoints. Publisher/consumer QoS can be incompatible, queues can retain stale data, the graph trigger or sensor may not execute, frames/time can be invalid, and bandwidth/consumer work can miss deadlines. Trace one sample end to end.

Why is GUI FPS not simulation throughput?

GUI FPS describes render/app updates. Physics steps, simulated seconds per wall second, sensor production, environment steps, and p95 latency are separate quantities. Define a workload and measure the rate that matches the engineering claim.

What makes a change causal evidence rather than a lucky improvement?

The hypothesis predicts a unique signal; one variable moves that signal; restoring the baseline restores the failure; an unaffected counter-example stays unchanged; and the candidate fix passes nominal, held-out, safety, and performance gates.

Version and API guard

Keep the learning path aligned with Isaac Sim 6.0

Use now

  • Installed 6.0.0-rc.59 identity in every run
  • Isaac Sim 6.0/6.0.1 documentation with local API verification
  • isaacsim.sensors.experimental.physics for current physics sensors
  • Isaac Lab when parallel learning/randomization becomes necessary

Avoid category mistakes

  • Do not install deprecated standalone Isaac Gym/IsaacGymEnvs
  • Do not copy 4.x/5.x imports into 6.0 without checking
  • Do not read runtime handles before initialization/reset
  • Do not let two loop owners advance physics
