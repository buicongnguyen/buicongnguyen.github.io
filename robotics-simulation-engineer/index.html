Important definitions

Know these well enough to diagnose a failure

Memorize the contract and the failure mode—not only the vocabulary. Use the linked deep resource route when a definition is still fuzzy.

USD stage, prim, and layer

A stage is the composed scene, a prim is a named scene object, and layers contribute ordered property opinions.

Failure to catch: a session-layer edit disappears, or a stronger layer silently overrides the value you tuned.

Link, joint, and articulation

A link is a rigid body; a joint constrains relative motion; an articulation solves a connected multibody tree as one system.

Failure to catch: the joint axis, parent/child frame, limit, or articulation root is wrong.

Visual versus collision geometry

Visual meshes create appearance. Collision shapes define the geometry the physics solver actually contacts.

Failure to catch: a beautiful high-poly or concave mesh causes slow, noisy, or impossible contact.

Mass, center of mass, and inertia

Mass sets translational resistance, the center of mass locates it, and the inertia tensor sets rotational resistance about an inertial frame.

Failure to catch: non-positive or physically impossible inertia makes the robot explode or rotate unrealistically.

Frame and unit convention

A value is meaningful only with a named reference frame, axis/handedness convention, unit, and timestamp; poses also require a rotation convention.

Failure to catch: meters/millimeters, degrees/radians, quaternion order, or optical/body frames are silently mixed.

Verification, validation, and calibration

Verification asks whether the implementation matches its specification; validation asks whether it matches the intended observable; calibration estimates parameters from data.

Failure to catch: a test that proves code consistency is presented as proof of physical accuracy.

Forward and inverse kinematics

Forward kinematics maps joint coordinates to a pose. Inverse kinematics finds joint coordinates for a desired pose, often with multiple or no solutions.

Failure to catch: an unreachable target or frame mismatch is misdiagnosed as a controller problem.

Contact, friction, and restitution

Contact constraints limit and resolve interpenetration according to geometry, offsets, timestep, and solver settings; friction opposes tangential motion and restitution controls rebound.

Failure to catch: extreme friction is used to hide bad collision shapes, mass, gains, or gripper force.

Timestep, substep, and solver iteration

The timestep advances simulation time; substeps divide integration; solver iterations improve constraint convergence within a step.

Failure to catch: changing dt also changes the controller or sensor rate and invalidates the comparison.

PD control and critical damping

PD control uses position and velocity error. Critical damping is a useful single-DOF starting estimate, not a universal articulated-robot gain.

Failure to catch: gains ignore effective inertia, units, command rate, saturation, and payload.

Actuator model

The actuator contract includes command mode, gear/transmission, effort and velocity limits, saturation, deadband, friction, and delay.

Failure to catch: an ideal unlimited drive makes a task look easier than any physical motor can achieve.

Simulation time, wall time, and RTF

Simulation time belongs to the virtual world; wall time is elapsed real time; real-time factor is simulated time divided by wall time.

Failure to catch: a ROS node uses wall time while the simulator pauses or runs faster than real time.

URDF, MJCF, SDF, and USD

URDF describes robot trees, MJCF is MuJoCo-native, SDF covers models and worlds, and USD composes rich scenes and schemas.

Failure to catch: successful conversion is mistaken for identical joints, contacts, drives, and solver semantics.

ROS graph, QoS, TF, and clock

Nodes exchange topics, services, and actions; QoS controls delivery; TF relates timestamped frames; /clock provides simulation time.

Failure to catch: matching topic names still fail because QoS, frame IDs, timestamps, or use_sim_time disagree.

Calibration versus randomization

Calibration/system identification estimates parameters from data. Domain randomization samples justified uncertainty around a model.

Failure to catch: a broad randomization range hides a biased nominal model instead of explaining it.

Sensitivity and identifiability

Sensitivity measures how an observable changes with a parameter. A parameter is identifiable only when the available excitation/data can distinguish its effect.

Failure to catch: friction, damping, inertia, and delay are fit together even though many combinations explain the same trace.

Solver convergence and contact offsets

Residual/convergence describe how well constraints are solved. Contact and rest offsets control when contact is generated and the separation the solver targets.

Failure to catch: more iterations appear to fix contact while the collider, offset, timestep, or mass ratio remains wrong.

Determinism and reproducibility

Determinism concerns repeated outcomes; reproducibility also records code, config, versions, hardware, seed, commands, and tolerance.

Failure to catch: “same seed” is treated as sufficient despite changed assets, parallel ordering, or GPU/runtime versions.

Headless and vectorized simulation

Headless runs without an interactive UI; vectorized simulation batches many environments to amortize work and exploit parallel hardware.

Failure to catch: Python loops, rendering, sensors, or synchronization erase the expected GPU scaling.

Fidelity and sim-to-real evidence

Fidelity is accuracy for declared observables and conditions. Sim-to-real evidence requires measured performance on physical hardware.

Failure to catch: a realistic render or synthetic held-out test is presented as proof of real-world transfer.

Learn

  • SI units, handedness, quaternion ordering, and angle conventions.
  • Simulation timestep, control period, sensor period, and wall time.
  • Seeds, deterministic expectations, config hashing, and software provenance.

Build

  • Create one command that starts a headless scene and advances 1,000 steps.
  • Record simulator, driver, OS, hardware, dependencies, seed, and config.
  • Log simulation time, step count, finite-state checks, and shutdown result.
  • Put frame/unit/manifest tests in hosted pure-Python CI as soon as they exist.

Evidence

  • environment.md, configs/smoke.yaml, and a required-field manifest schema.
  • preflight.py, frame/unit fault tests, raw state trace, and two same-seed summaries.
  • A bounded smoke command with documented exit codes, duration, and known determinism limits.

Applied definitions and invariants

Experiment identity
Commit and dirty state + config and asset hashes + seed + Sim/Kit/Python/driver/hardware manifest. A seed alone is not provenance.
Frame composition
TA,C = TA,BTB,C; test RᵀR ≈ I, det(R) ≈ +1, units, quaternion order, and active/passive convention.
Clock contract
Physics time is tk = kΔtp. Control, rendering, and sensor periods are separate and should use declared integer decimation where possible.
Verification versus validation
Verification checks implementation against specification; validation checks declared outputs against evidence for an intended use.

Failure diagnosis

  • Import/startup error: confirm C:\isaacsim-6.0.1\python.bat and create SimulationApp before Omniverse imports.
  • 100× scale error: inspect metersPerUnit, mesh scale, meters versus centimeters, and radians versus degrees.
  • Same seed differs: compare manifests, RNG ownership, async order, assets, and runtime before blaming PhysX.
  • Process hangs: reduce to initialize → bounded update/step → close; then inspect callbacks and background work.
  • Edit disappears: identify the USD layer/edit target and whether the value existed only in the session layer.

Practical lab sequence

  1. Platform fingerprint

    Write preflight.py to capture exact runtime, OS, GPU, memory, stage units/up axis, rates, Git state, config hash, and resolved assets.

    Output

    manifest.json, environment.md, and a schema that rejects missing required fields.

    Pass condition

    Wrong Python or incomplete provenance returns a nonzero exit code instead of silently continuing.

  2. Frames and units fault test

    Output

    tests/test_frames_units.py with clean, wrong-scale, and wrong-quaternion fixtures.

    Pass condition

    Clean transforms agree within a units-based tolerance and both planted faults fail the intended assertion.

    Output

    state.csv, summary.json, console log, and seed-42/42/43 comparison.

    Pass condition

    Final sim time matches steps × dt; same-seed initial conditions agree within declared tolerance.

8–12 hours

Rigid-body dynamics and contact fidelity

Turn gravity, integration, constraints, friction, restitution, and contact compliance into measured experiments rather than visual guesses.

Learn

  • M(q)q̈ + C(q,q̇)q̇ + g(q) = τ + Jᵀf.
  • Mass, center of mass, inertia, constraints, and energy.
  • Static versus kinetic friction, restitution, contact stiffness, and damping.
  • Timestep, substeps, solver iterations, penetration, stability, and throughput.

Build

  • Drop test from a known height; compare fall and rebound timing.
  • Inclined-plane or slide test; estimate the friction threshold and deceleration.
  • Simple pendulum; compare measured and small-angle period.
  • Sweep timestep and solver settings without changing the model.

Evidence

  • Versioned free-fall, rebound, friction, and pendulum configs plus raw CSV/JSON traces.
  • Regenerable report naming formulas, assumptions, observable definitions, units, and resolution.
  • Held-out parameter prediction and a deliberately bad/fixed numerical case.

Applied definitions and equations

Multibody dynamics
M(q)q̈ + C(q,q̇)q̇ + g(q) = τ + J(q)ᵀλ. The contact term is constrained by geometry and solver semantics.
Contact idealization
Gap φ(q) ≥ 0, normal force λn ≥ 0, and complementarity φλn = 0; practical solvers can permit numerical penetration.
Analytical baselines
thit = √(2h/g), e ≈ √(hrebound/hdrop), μs ≈ tan θc, and T ≈ 2π√(L/g) under their stated assumptions.
Resolution study
Compare the same observable at Δt, Δt/2, and Δt/4; choose resolution from convergence and measurement needs, not a universal error percentage.

Failure diagnosis

  • Impact error ≈ one step: test event/time quantization by reducing dt before changing gravity.
  • Wrong slide threshold: inspect static/dynamic material assignment, combine mode, incline frame, and residual velocity.
  • Pendulum period mismatch: use pivot-to-COM length and quantify amplitude before tuning damping.
  • Jitter/explosion: check initial overlap, mass ratio, contact offset, timestep, then solver convergence—one change per rerun.
  • Lower dt changes everything: remove controllers/sensors from canonical tests and record every rate.

Practical lab sequence

  1. Free fall and rebound

    Run two or three heights; detect contact from contact data; compare impact time/velocity, rebound height, and restitution at three timesteps.

    Output

    Raw traces, contact-event detector, formula/assumption table, convergence plot, and restitution estimate.

    Pass condition

    Chosen timestep reaches the predeclared convergence criterion or the unresolved discrepancy is reported.

  2. Static and dynamic friction

    Bracket first sustained slip on an incline, then estimate kinetic friction from a horizontal slide and test it at a held-out angle/velocity.

    Output

    Material/combination manifest, threshold plot, deceleration fit, uncertainty, and held-out prediction.

    Pass condition

    The estimate predicts the held-out observable within a tolerance tied to angle/time measurement resolution.

  3. Pendulum and solver fault isolation

    Compare small and larger initial angles, sweep timestep/iterations, then introduce one bad overlap or mass ratio and repair it.

    Output

    Angle/period/energy plots plus bad/fixed manifests differing in one intended variable.

    Pass condition

    The report separates analytical-approximation, model-parameter, discretization, and solver errors.

Applied definitions and equations

Tree and frame contract
An open-chain model has one root, connected/acyclic parentage, and joint axes expressed in named joint frames. Verify canonical FK, not only tree shape.
Parallel-axis theorem
IO = IC + m((dᵀd)I₃ − ddᵀ). Express inertia about the COM first, then transform it deliberately.
Primitive inertia
For a box: Ixx = m(b²+c²)/12 with cyclic permutations. Record dimensions, density/mass source, axes, and units.
Conversion semantics
URDF source and imported USD may differ in base mode, collider approximation, articulation root, drives, self-collision, and defaults. Successful import is not equivalence.

Failure diagnosis

  • Explodes on first step: inspect initial overlap, impossible/tiny inertia, base constraint conflict, and ground penetration.

Effort PD

    Generate noisy traces from withheld parameters; design separate free, step/chirp, and slide/contact excitations; rank finite-difference sensitivities.

    Output

    Truth manifest kept outside fitting input, trace schema, sensitivity matrix/plot, and selected identifiable parameter subset.

    Pass condition

    Chosen parameters are recovered within predeclared synthetic tolerance; correlated/weak parameters are explicitly excluded.

  2. Bounded fit and held-out validation

    Time-align/resample traces, fit one or two supported parameters with robust least squares, then score untouched trajectories and residual structure.

    Output

    Optimizer config, parameter profile/uncertainty, before/after held-out metrics, residual autocorrelation, and bound-hit explanations.

    Pass condition

    Held-out improvement exceeds repeat variability; otherwise the result is correctly reported as no demonstrated benefit.

  3. Evidence ladder

    Optionally record a phone-video pendulum or block-on-ramp trace; otherwise use a withheld simulator or MuJoCo and label it sim-to-sim/cross-simulator.

    Output

    Source/provenance note, calibration/validation split, targeted-calibration versus broad-randomization comparison, and claim-boundary paragraph.

    Pass condition

    Every report sentence distinguishes synthetic, cross-simulator, or physical evidence and limits the claim to measured observables.

Applied definitions and measurements

RTF and steps/s
RTF = simulated elapsed time / wall elapsed time. Specify physics or control steps; GUI FPS is neither measure.
Environment-steps/s
num_envs × control_steps/s. Larger batches can improve throughput while increasing per-step latency.
Warmup and synchronization
Exclude compilation/cache/GPU-clock warmup and synchronize queued GPU work before timing boundaries that require completion.
p50/p95 and variation
Report median/tail latency and repeat variation; an optimization should exceed run noise while preserving correctness tolerances.
CI split
Hosted CI verifies pure-Python schema/math/config logic. Local or self-hosted RTX validation proves Isaac physics/reset/sensor/ROS behavior.

Failure diagnosis

  • Great “FPS,” poor physics: define the measured loop and compare simulated time, control steps, and wall time.
  • Benchmark is noisy: separate startup/shader compilation, warmup, GPU synchronization, thermal/background load, and fixed repetitions.
  • Sensors destroy throughput: isolate resolution, count, tick rate, rendering mode, readback, DDS, and host-device transfer.
  • Scaling stops: log VRAM/RAM, contacts, collision complexity, CPU fallback, Python loops, and reset cost.
  • CI badge overclaims: list exactly which tests ran on hosted CPU and which require the local Isaac/RTX environment.

Engineering reference

Metrics and invariants worth memorizing

Free fall

t ≈ √(2h / g)

Use before contact. Compare simulated time-to-impact with the analytical baseline and state the integration tolerance.

Pendulum

T ≈ 2π√(L / g)

The small-angle result checks gravity, length, constraint behavior, timestep, and damping without a controller.

Critical damping

ccrit = 2√(km)

A useful single-DOF starting point; articulated effective mass changes with configuration.

Tracking RMSE

√mean((qsim − qref)²)

Report per joint and aggregate with explicit units, alignment, filtering, and evaluation interval.

Real-time factor

RTF = simulated time / wall time

RTF above one is faster than real time. Also report workload, rendering, sensors, warmup, and hardware.

Physical inertia

I₁ + I₂ ≥ I₃

Principal moments must be positive and satisfy all permutations of the triangle inequality.
