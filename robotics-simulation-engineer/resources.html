The 45-minute rule

  1. Open only the resource named by today’s task.
  2. Write the requested definitions or decisions in your own words.
  3. Stop after 45 minutes and implement the smallest experiment.
  4. Return only when a measured failure creates a specific question.

Documentation is input. A command, artifact, metric, and engineering note are evidence.

Build-indexed resource map

Nine stages from first launch to application evidence

The course’s learning flow remains authoritative. This page groups references by first use; robot-model audit and canonical-physics experiments deliberately iterate across Days 2–5. Stages 0–5 are the application core, Stages 6–7 deepen the evidence, and Stage 8 is optional.

Stage 0 · Days 1–2

Environment, workflows, and version manifest

First answer: which runtime, Python, physics backend, renderer, launch mode, units, and machine produced the result?

Course companion45 minutes

Reasoning & Code Flow Atlas

Extract: app-before-import lifecycle, reset barrier, one-step cause/effect, data contracts, sequence ordering, state transitions, and CIDER reasoning.

Build: annotate your first runner with the eight instrumentation checkpoints and emit one complete reset/step/terminal bundle.

Stop when: you can point to the first code boundary that would reveal a wrong value.

Start here30 minutes

NVIDIA: Getting Started with Isaac Sim

Extract: stage/world setup, simulation loop, assets, and the difference between UI and scripted workflows.

Build: complete only the minimum path needed to launch and inspect one scene.

Stop when: you can explain where physics steps and rendering steps occur.

Official docs20 minutes

Isaac Sim Workflows

Extract: GUI, extension, standalone Python, and headless tradeoffs.

Build: choose standalone Python for the public experiment runner and document why.

Stop when: one bounded headless command exits successfully twice.

Compatibility15 minutes

Isaac Sim Requirements

Extract: driver, GPU/VRAM, RAM, storage, and supported OS assumptions.

Build: an environment.md with exact Sim/Kit/Python/driver/GPU/RAM values.

Stop when: every benchmark can link to that manifest.

Isaac Sim Python and OpenUSD foundations

Core API Hello World

Build: add a dynamic cube, log pose for 1,000 steps, reject NaN/Inf, and exit cleanly.

Python Scripting Concepts

OpenUSD Fundamentals

Stage 2 · Day 3

Rigid-body dynamics, contact, and numerical validation

Use canonical experiments to separate bad mass properties, integration, contact, and solver settings before adding robot control.

Core40 minutes

Physics Simulation Fundamentals

Extract: physics timestep, rendering interval, solver settings, materials, collision, and articulation behavior.

Build: free-fall, pendulum, and inclined-plane tests with a timestep/substep sweep.

Stop when: plots compare expected and observed values with units and tolerance.

PhysX depth30 minutes

Omniverse Collision Behavior Guide

Extract: collider approximations, contact/rest offsets, penetration, continuous collision detection, and mass-ratio risks.

Build: one deliberately bad collision case and the measured fix.

Stop when: the fix changes one variable and explains the mechanism.

University theoryAs needed

MIT Underactuated Robotics: Contact

Extract: unilateral constraints, complementarity, friction cones, impacts, and why contact is numerically hard.

Build: annotate one grasp failure with the contact constraints that should be active.

Stop when: you can distinguish geometry, material, solver, and controller hypotheses.

TextbookReference

Modern Robotics

Extract: frames, rigid motions, Jacobians, dynamics, and computed-torque/control concepts relevant to the current failure.

Build: derive or numerically check one FK/Jacobian/dynamics quantity from the robot model.

Stop when: the result agrees with the simulator within a declared tolerance.

Stage 3 · Days 2–5

Robot model audit, articulations, actuators, and gains

Treat import as the beginning of validation—not proof that the robot model is correct.

Model source30 minutes

URDF Physical and Collision Properties

Extract: visual, collision, inertial origin, mass, inertia tensor, joints, and units.

Build: a model-card table for every movable link and joint.

Stop when: automated checks reject missing or impossible mass properties.

Import35 minutes

Isaac Sim URDF Import Tutorial

Extract: base mode, articulation root, joint drives, collision, mimic joints, self-collision, and saved USD behavior.

Build: import the built-in UR10 example and compare its generated USD against the source contract.

Stop when: every imported difference is accepted, repaired, or documented.

Control lab30 minutes

Tuning Joint Drive Gains

Extract: drive types, stiffness, damping, step response, sinusoidal response, effort limits, and payload dependence.

Build: scripted step/chirp tests with overshoot, settling time, RMSE, and peak effort.

Stop when: the gain manifest passes the declared test for three payloads.

Actuator depth25 minutes

Isaac Lab Actuator Concepts

Extract: implicit/explicit actuators, simulation versus motor limits, saturation, armature, friction, and delay.

Build: add at least effort/velocity saturation and command delay to the scripted controller.

Stop when: plots show when and why the actuator saturates.
