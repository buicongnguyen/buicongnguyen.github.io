Mental model

ROS 2 is a launch-time dependency graph, not a global toggle

Isaac Sim loads a ROS backend and middleware into its process. The launching terminal determines which libraries and variables it inherits. A fresh process is the isolation boundary.

Switch protocol

Stop → clear → select → launch → prove

A switch completes only after the old processes are gone and the new identity bundle is recorded.

S0One mode activeExperiment running
StopSave → close Isaac → stop nodes/router
S1QuiescentNo Isaac, Kit, ROS, or router process
ClearClose terminals → fresh shell
S2Select one contractJazzy/Zenoh or Humble/Fast DDS
LaunchDiscovery → simulator → nodes → Play
S3Prove identity and dataEnvironment → graph → clock → payload

Windows Jazzy → WSL Humble

  1. Save manifest, rosbag, and logs.
  2. Close Isaac, Pixi shells, and Zenoh.
  3. Confirm no intended Kit/ROS/router process remains.
  4. Use a fresh CMD with the Humble launcher block.
  5. Source only Humble in Ubuntu 22.04.
  6. Prove identity and /clock.

WSL Humble → Windows Jazzy

  1. Stop WSL nodes and close Isaac.
  2. Optionally use wsl --shutdown after saving work.
  3. Close the Humble CMD.
  4. Open three fresh Pixi terminals.
  5. Start Zenoh, simulator, then CLI.
  6. Prove identity and /clock.
Domain IDs are defense in depth, not the primary switch. They reduce accidental discovery but cannot remove inherited library paths or workspace overlays. Fresh terminals and one simulator remain mandatory.

Isolation ladder

Diagnose the first broken contract—not the loudest symptom

1 · Wrong identity or mixed environment

Print distribution, RMW, domain, executable, simulator, and workspace paths. If wrong, close the terminal and relaunch; do not repair a contaminated shell variable-by-variable.

2 · Simulator bridge not loaded

Confirm the ROS 2 Bridge extension, backend log, clock graph, and timeline. Fix backend loading before transport.

3 · Discovery process or transport missing

Windows: prove Zenoh started first. WSL: prove Fast DDS and the same domain on both sides, then inspect reachability.

4 · Topic exists but no messages arrive

Check Play state, publisher/subscriber counts, QoS compatibility, and whether the graph executes on the intended tick.

5 · Data arrives but is stale or wrong

Compare simulation time, header time, wall arrival, frame ID, TF, rate, ordering, and payload with internal sensor truth.

6 · Commands arrive but the robot does not move

Check type, freshness, controller ownership, joint ordering, units, limits, saturation, drive mode, and actuator input.
