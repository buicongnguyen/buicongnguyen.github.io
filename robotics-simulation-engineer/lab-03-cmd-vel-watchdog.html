Clock decision: Twist has no header stamp. The supplied watchdog uses monotonic receipt time so safety expiration continues even if simulation time pauses.

Steps 1–2

Open the same robot and inspect controller wiring

  1. Start the Lab 01 three-terminal Windows contract.
  2. Open Isaac Sim → Samples → ROS2 → Scenario → turtlebot_tutorial.usd.
  3. Require /clock, /joint_states, /tf, and /odom before control.
  4. Inspect the full 6.0 path: ROS2 Subscribe Twist → Scale To/From Stage Unit → Break 3-Vector → Differential Controller → Make Array → Articulation Controller.
  5. Confirm wheel tokens from actual state: wheel_left_joint, wheel_right_joint for the reference TurtleBot.

Subscriber

Topic /cmd_vel, Jazzy context, active graph tick.

Units + fields

Scale stage units, then split linear/angular vectors into the controller inputs.

Actuation

Make Array preserves wheel ordering; the articulation controller owns joint velocity targets.

Latch boundary: stopping a Twist publisher does not guarantee the Isaac subscriber/controller forgets its last value. The external steady-clock watchdog deliberately publishes zero. It is an educational runtime guard, not a certified hardware safety system.

Step 3

Prove direct motion before adding safety logic

$Launcher = "C:\Users\n\source\repos\issac_sim\robotics-simulation-engineer\Start-IsaacRosJazzy.ps1"
# Forward once
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.2}, angular: {z: 0.0}}"
# Explicit zero
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist "{linear: {x: 0.0}, angular: {z: 0.0}}"

Check wheel velocities and odometry together. If motion direction is wrong, inspect wheel axes/order and body-frame convention before introducing a sign correction.
