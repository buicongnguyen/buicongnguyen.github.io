Discovery is not data validity. A useful image requires coherent frame, stamp, encoding, dimensions, stride, payload, calibration, QoS, and delivery capacity.

Step 1

Use and inspect the reference camera scene

  1. Open Isaac Sim → Samples → ROS2 → Scenario → turtlebot_tutorial.usd.
  2. Require the prior Clock/state/control gates.
  3. Inspect camera prim, render product, and Camera Helper nodes.
  4. Do not add duplicate helpers if the sample already publishes RGB/depth.
  5. Remember: each Camera Helper retrieves one data type; RGB, depth, point cloud, and CameraInfo can use separate helpers.

Step 2

Discover actual topic names before copying commands

$Launcher = "C:\Users\n\source\repos\issac_sim\robotics-simulation-engineer\Start-IsaacRosJazzy.ps1"
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic list -t | Select-String -Pattern "camera|image|depth|point"
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic type /camera_1/rgb/image_raw
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic info /camera_1/rgb/image_raw --verbose
pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher ros2 topic echo /camera_1/rgb/camera_info --once

The shipped scenario commonly uses /camera_1/rgb/image_raw and /camera_1/rgb/camera_info. Replace them with the names discovered in your Stage.

Step 3

Run the bounded Image contract probe

pwsh -NoProfile -ExecutionPolicy Bypass -File $Launcher python "C:\Users\n\source\repos\issac_sim\robotics-simulation-engineer\lab-assets\camera_probe.py" --topic /camera_1/rgb/image_raw --timeout 15

Shape

width,height,step > 0

Payload bytes must be at least step × height.

Meaning

encoding + optical frame_id

Do not infer color/depth units from values alone.

Time

header stamp advances with `/clock`

Timestamp should represent acquisition, not consumer receipt.
Probe gate: JSON reports ok: true. Repeat against the discovered depth Image topic and record its encoding/official units.

Step 4

Validate optical geometry before adding noise

Geometry checklist
Optical axes+x image right; +y image down; +z forward through image plane
Frame identityImage and CameraInfo use the same frame_id
ResolutionImage and CameraInfo width/height agree
IntrinsicsCameraInfo matrix matches current resolution
ExtrinsicTF places optical frame under intended robot link
Known targetright/left motion and known distance agree before noise
