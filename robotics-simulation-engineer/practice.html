Answer correctly, not just confidently

Use CIDER for every diagnostic and interview answer

State the contract and the evidence before proposing a fix. A good answer includes a result that would falsify its own hypothesis.

C · Contract

What should be true?

Name the invariant, boundary, lifecycle phase, unit, frame, time, rate, and failure behavior.

I · Identity

What is frozen?

Commit, config/assets, runtime, hardware, seed, x₀, action trace, and workload.

D · Discriminate

What separates causes?

Rank hypotheses and run one experiment for which they predict different results.

E · Evidence

What changes the decision?

Point to the first bad sample or boundary comparison—not only the final symptom.

R · Repair/regress

What remains true later?

Change one variable, restore and counter-test, land a regression, and state the limit.

Knowledge map

Six ideas that connect the whole role

Frames are contracts

Every pose, wrench, sensor value, and joint axis needs a named frame, convention, and timestamp.

Fidelity is task-relative

A model is “high fidelity” only with respect to declared observables, operating conditions, and error tolerances.

Defaults are parameters

Unwritten solver, material, actuator, import, and sensor defaults still shape the result and must be captured.

Control changes physics

Gain, rate, saturation, delay, and command semantics can dominate observed behavior even with a valid rigid-body model.

Randomization needs a prior

Ranges should follow measurement, identification uncertainty, or sensitivity—not an arbitrary common percentage.

Reproducibility is evidence

Commit, config, seed, hardware, commands, raw results, and known limitations turn a demo into reviewable engineering.

Failure diagnosis

Six senior-level debugging walkthroughs

A strong answer orders hypotheses by likelihood and information gain, then names the evidence that would change the decision.

1. An imported robot explodes on the first physics step.Model bring-up

First isolate

  1. Disable controllers, gravity, and self-collision independently; start from a known pose.
  2. Check length/mass units, NaN or zero masses, inertia validity, joint axes, and impossible limits.
  3. Visualize collision shapes and find initial overlaps or detailed dynamic triangle meshes.
  4. Advance one step at a time and record the first body, constraint, or contact that diverges.

Do not start with

Blindly raising solver iterations or damping. Those changes can mask symptoms without repairing an invalid model.

Decision evidence

A minimal body/joint/contact reproducer, model-validator output, first-step forces/impulses, and before/after finite-state test.

2. A gripper holds visually, but the object slowly slips or chatters.Contact

Ranked hypotheses

  1. Normal force or actuator effort is insufficient or saturating.
  2. Friction combine mode, anisotropy, contact patch, or material assignment differs from expectation.
  3. Timestep/contact stiffness/damping creates penetration and unstable impulses.
  4. Collision proxies leave a smaller or tilted contact area than the visual meshes suggest.

Experiment

Log normal/tangential contact forces, slip velocity, commanded/applied effort, and penetration while sweeping one parameter family at a time. Compare against a simple friction-cone bound.

3. Camera and LiDAR data arrive, but localization jumps and TF reports extrapolation.ROS 2 time

Trace the clock

  1. Confirm every node uses simulation time and receives the same /clock.
  2. Compare acquisition stamps, publication stamps, TF buffer coverage, and rosbag playback clock.
  3. Check static versus dynamic transform publishers and optical-frame axes.
  4. Measure sensor rate and intentional latency; do not rewrite stamps to “now” to hide the fault.

Evidence

A time-aligned trace showing sensor stamp, transform availability interval, lookup time, queue delay, and corrected residual.

4. The same seed is stable locally but occasionally fails in headless CI.Reproducibility

Separate causes

  1. Pin asset/dependency versions and compare hardware, driver, thread count, and solver backend.
  2. Capture the first divergent state, not only the final success/failure flag.
  3. Look for unordered iteration, async startup, wall-time dependencies, parallel reductions, and stale reset state.
  4. Decide whether bitwise determinism is required; otherwise test bounded invariants or distributions.

CI response

Retain the seed, config, first-difference trace, logs, and replay command as failure artifacts. Use tolerances justified by the observable, not by what makes CI green.

5. GPU throughput scales well to 256 environments, then plateaus.Performance

Measure by workload slice

  1. Benchmark physics-only, then add contacts, sensors, rendering, policy inference, logging, and resets.
  2. Warm up and synchronize timing boundaries; record GPU memory and utilization.
  3. Profile Python loops, tensor allocation, host-device copies, readback, and per-environment scene mutations.
  4. Compare step cost and amortized reset cost across environment counts.

Good conclusion

Name the bottleneck and its evidence. “GPU simulation does not scale” is not a diagnosis.

6. Calibrated friction fits one trajectory but worsens another.Identification

Likely issues

  1. The calibration motion did not excite friction separately from damping, delay, or actuator gain.
  2. A single coefficient cannot represent direction, speed, load, contact patch, or surface changes.
  3. Time alignment, sensor bias, or preprocessing contaminates the objective.
  4. The optimizer overfit one trace or found a non-unique parameter combination.

Next experiment

Design multiple excitation regimes, split calibration from validation, run sensitivity/identifiability checks, and report parameter uncertainty alongside held-out residuals.

Implementation practice

Six coding and configuration drills

Solve with tests first. A short correct validator or benchmark harness is more persuasive than a large unmeasured simulator demo.

1. Validate a rigid body’s mass and inertia tensor.Python · NumPy

Task

Implement validate_inertia(mass, inertia, tol). Return structured errors for shape, finiteness, symmetry, mass positivity, eigenvalue positivity, and principal-moment triangle inequalities.

Acceptance tests

  • Valid box and sphere tensors pass.
  • Negative mass, asymmetric tensor, negative eigenvalue, and impossible principal moments fail with distinct messages.
  • Near-boundary values use an explicit scale-aware tolerance.

Follow-up

Extend it with the parallel-axis theorem and verify the shifted tensor by moving the center of mass.

2. Parse a URDF joint graph and detect structural errors.Python · XML

Task

Read link and joint elements, build parent-to-child adjacency, find roots, detect duplicate parents, missing references, disconnected links, and cycles, then output a topological traversal.

Acceptance tests

  • A valid chain and branched tree pass.
  • A cycle, two roots, orphan link, and unknown child fail.
  • Fixed and movable joints remain distinguishable.

Interview extension

Explain how you would represent a physical loop when the source format requires a tree.

3. Compose transforms without mixing quaternion conventions.Geometry

Task

Implement pose composition and inversion with a documented quaternion ordering. Normalize at API boundaries and reject zero-norm quaternions.

Acceptance tests

  • T * inverse(T) returns identity within tolerance.
  • Known 90-degree rotations compose in the correct order.
  • A ROS-style (x,y,z,w) adapter round-trips to the chosen internal ordering.
4. Design a friction calibration sweep.Experiment

Task

Given reference displacement and velocity traces, sweep static/kinetic friction and damping, align timestamps, compute weighted residuals, and retain the full result surface—not only the winner.

Acceptance tests

  • Calibration and held-out traces are separate.
  • Units and bounds are validated.
  • The report includes sensitivity and multiple near-optimal solutions.
5. Write a reset and determinism regression test.pytest

Task

Run several episodes with fixed seeds, reset between them, and assert finite states, joint/workspace bounds, object count, clean timestamps, and an explicitly chosen equality/tolerance policy.

Acceptance tests

  • A leaked object or stale controller state fails.
  • A NaN reports the first step and entity.
  • Failure artifacts include seed, config hash, and short state trace.
6. Build a fair parallel-simulation benchmark harness.Performance

Task

Benchmark multiple environment counts with warmup and repeated timed windows. Separate initialization, reset, physics-only, sensor-enabled, and rendered modes.

Acceptance tests

  • GPU timing boundaries synchronize correctly.
  • Median and dispersion are reported, not the fastest sample.
  • Output records hardware, software, workload, memory, and exact config.

Fast reference

Glossary

Articulation
A connected multibody system whose joint structure can be solved as a unit.
Broadphase
The fast collision stage that rejects pairs that cannot overlap before detailed tests.
Collision proxy
Simplified geometry used for stable, efficient contact instead of detailed visual geometry.
Domain randomization
Sampling model or observation parameters during training/evaluation to represent uncertainty.
Identifiability
Whether available data can uniquely or usefully constrain a model parameter.
MJCF
MuJoCo’s XML modeling format for bodies, joints, actuators, constraints, sensors, and defaults.
Principal moments
Eigenvalues of the inertia tensor along principal axes through the center of mass.
Real-time factor
Simulated elapsed time divided by wall-clock elapsed time.
SDF
Simulation Description Format used for robot models, environments, sensors, physics, and plugins.
Specific force
Non-gravitational force per unit mass measured by an ideal accelerometer.
TF
ROS transform system for time-indexed relationships among named coordinate frames.
URDF
ROS-oriented XML format for a robot’s links, joints, geometry, inertial properties, and extensions.
