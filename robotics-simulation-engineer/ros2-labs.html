Why this order is defensible: tuning cannot repair a malformed model; CI cannot validate an undefined contract; profiling cannot distinguish useful work from incorrect work; randomization cannot compensate for an uncalibrated nominal case.

Decision logic
No dataidentity → discovery → execution → publisher ownership
Data is wrongtype → dimensions → units → frame → timestamp → rate
Motion is wrongcommand latch → unit conversion → joint order → limits → contact
Result changesseed → reset state → warm-up → test duration → hidden parameters
Correct but slowrepeat baseline → CPU/GPU trace → change one variable → compare tails
Nominal passes, variants failinspect worst cases → validate ranges → improve controller/model → retest held-out set
