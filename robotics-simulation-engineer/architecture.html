System map · failure isolation · engineering evidence

See the whole simulator. Debug the lowest failed contract.

A robot simulation is a stack of contracts, not one scene. This field guide connects runtime identity, assets, physics, control, sensors, ROS 2, tasks, calibration, randomization, performance, and delivery. Use the maps to decide what to learn, locate the first broken boundary, run one discriminating experiment, and preserve the result as a regression test.

Prime directive

  1. Reproduce the exact failure.
  2. Find the lowest failed contract.
  3. Reduce it to the smallest subsystem.
  4. Change one variable and counter-test it.
  5. Keep the fix as an automated regression.

Never tune gains, friction, randomization ranges, or a policy around a broken model, reset, timing, or physics contract.

What to focus on first

Learn in dependency order, apply before the entire map is complete

The fastest credible job path is one narrow, measured manipulation pipeline. Finish the priority-zero contracts, publish a bounded v0.1, and improve it while applying. Breadth is useful only after the core pipeline is reproducible.

P0 · stop-ship

Make the world trustworthy

  1. M0: runtime, configuration, seed, reset, logs.
  2. M2: units, frames, joint tree, mass and inertia.
  3. M3: USD ownership, scene composition, lifecycle.
  4. M1: contact, timestep, solver, energy checks.

Exit gate: a controller-free canonical test replays deterministically and fails loudly.

P1 · application core

Build the useful pipeline

  1. M4: one-joint response, limits, saturation, rates.
  2. M5: internal sensors, time, TF, QoS, watchdogs.
  3. M6: scenario, reset, metrics, replay, evaluation split.

Exit gate: a seeded task produces traces, success metrics, and a replayable failure packet.

P2/P3 · fidelity and scale

Calibrate, stress, then optimize

  1. M7: identify parameters on a fit split; validate held out.
  2. M8: randomize justified uncertainty; test nominal and held out.
  3. M9: profile, scale, CI gates, and reproducible delivery.

Exit gate: measured robustness and throughput gains do not hide nominal regressions.

Defer during the fast track: a second simulator, custom C++, advanced reinforcement learning, humanoids, GR00T, and hardware-in-the-loop. You do not need the legacy standalone Isaac Gym package. Use Isaac Sim now; add a version-compatible Isaac Lab environment only when the M8 parallel-training experiment needs it.
Not having a physical robot is acceptable for this portfolio stage. Demonstrate transfer engineering with clean validation, sensitivity analysis, held-out scenarios, cross-simulator checks, uncertainty manifests, and domain randomization. Label the result transfer-ready simulation evidence, not physical sim-to-real validation. A truthful boundary is stronger than an unsupported hardware claim.

Layered system architecture

Intent flows downward; measurements and evidence flow upward

A symptom may appear high in the stack while its cause lives lower. A task failure can originate in a stale clock; a control failure can originate in a joint axis; a contact failure can originate in scale. Start at the bottom and stop at the first broken invariant.

Ownership rule: the task layer orchestrates the system but does not own physics, sensor, transport, or timing semantics. Calibration and performance cross every layer. Change a parameter in its owning, versioned manifest—never as an invisible live-stage adjustment.

Contracts at every boundary

state

Name, order, shape, dtype, valid range, reset value, and missing-data rule.

time

Clock source, timestamp meaning, timestep, rate, latency, ordering, and timeout.

frame + unit

Parent/child frames, axis convention, handedness, SI unit, and quaternion ordering.

limits + rate

Joint limits, velocity/effort bounds, saturation location, decimation, and watchdog.

ownership

Exactly one writer; explicit source of truth; authored opinion versus composed result.

configuration

Schema, default, override precedence, validation, immutable snapshot, and hash.

provenance

Commit, dirty state, runtime build, asset hashes, hardware, command, and seed.

failure

Error code, first bad step, retained traces, termination class, and retry policy.

Configuration forward

Validate before launch, snapshot the resolved values, hash them, and attach the snapshot to every episode. A calibration result creates a new manifest; it does not silently mutate a live asset.

Measurements backward

Log the applied action—not only the requested target—plus state, contact, sensor timestamps, terminal reason, and resource metrics at their native rates.

Two kinds of replay

A ROS bag replays messages. An episode bundle reconstructs model, configuration, seed, reset state, action trace, and runtime. One cannot substitute for the other.

Time and rate architecture

Never use “the simulation runs at 60 Hz” without naming which clock or loop.

Control tick|——·——|——·——|Decimation or explicit update period; logs target and applied effort.
Sensor acquisition|————·————|——·Exposure/acquisition time is distinct from publish and consumer receipt.
Render tick|——————·——————|May be disabled or slower than physics; GUI FPS is not simulation throughput.
ROS simulation timet₀ → t₁ → t₂ → t₃All consumers must agree on the clock source and reset/jump behavior.
Wall time0 s → 1 s → 2 sUsed to compute real-time factor: simulated duration divided by wall duration.
Local build note: the packaged clock.py example exposes sim_time and manual_time. Do not document it as a verified /clock publisher until your actual ROS graph confirms the topic and message contract. The bundled bridge libraries are also not a complete ROS 2 CLI, colcon, launch, or rosbag installation.

Failure-isolation operating system

Reduce uncertainty before changing the system

Debugging is an experiment-design problem. A change that makes the symptom disappear is not enough; the test must distinguish plausible causes and survive restoration and counter-testing.

01Capture

Save the exact command, identity bundle, seed, initial state, actions, and first bad step.

02Freeze

Disable uncontrolled randomness and freeze configuration, assets, rates, and workload.

03Strip

Remove policy, ROS, sensors, rendering, contact, or extra joints until the failure remains.

04Instrument

Measure the boundary immediately before and after the first broken invariant.

05Rank

List hypotheses by evidence and cost; include a prediction that could falsify each.

06Change one

Alter one causal variable while holding the rest of the resolved manifest fixed.

07Counter-test

Restore baseline, repeat, and test a case where the proposed cause predicts no effect.

08Regression

Keep the minimal reproduction, threshold, expected signature, artifact, and owner.

Practical fault-isolation playbooks

Start from an invariant, not a favorite parameter

Each playbook follows observation → invariant → minimal test → ranked hypotheses → one-variable experiment → regression artifact.

A · Isaac Sim will not start, import, or repeat reliably
ObservationStartup crash, missing import, asset failure, or nominally identical runs diverge.
First invariantBundled Python, exact VERSION, extensions/config, seed, initial state, dt, and shutdown are known.
Minimal testCompatibility check, then the packaged standalone hello-world headless—no project asset or ROS.
Ranked hypothesesWrong interpreter; API/version mix; extension/config mismatch; first asset fetch; driver/memory; stale global state.
Regression artifactEnvironment probe plus a bounded headless smoke test with identity JSON and exit code.
Set-Location C:\isaacsim
Get-Content .\VERSION
.\isaac-sim.compatibility_check.bat --no-window --/app/quitAfter=10
.\python.bat .\standalone_examples\api\isaacsim.simulation_app\hello_world.py --no-window

One-variable experiment: run the same minimal script with C:\isaacsim\python.bat and the failing interpreter. Do not compare a project script with hello-world and call the interpreter causal.

B · Robot explodes, falls apart, or moves in the wrong direction
ObservationNaNs, extreme velocity, constraint failure, joint inversion, or first-step displacement.
First invariantTree, SI scale, base, quaternion order, mass/inertia, axes, limits, collision separation, and one command owner are valid.
Minimal testController off; ground removed; gravity off then on; move one joint ±0.05 rad and inspect state before/after first step.
Ranked hypothesesUnit/axis error; initial overlap; base/limit conflict; invalid inertia or mass ratio; command units; conversion; solver settings.
Regression artifactHeadless import audit, finite-state assertion, joint-direction table, overlap check, and 100-step stability trace.

One-variable experiment: toggle self-collision with all other properties frozen. If the first bad pair changes, inspect geometry and adjacency; do not “solve” it with more damping.

C · Contact jitters, slips, penetrates, or tunnels
ObservationUnstable grasp, chatter, excessive penetration, missing contact, or friction that changes unpredictably.
First invariantCollision proxies, materials/combine rule, mass/inertia, contact/rest offsets, dt, solver, and non-teleport motion are explicit.
Minimal testOne block on one plane: settle, incline/slide threshold, drop, and slow push before using the gripper.
Ranked hypothesesBad geometry; scale/mass/inertia; insufficient temporal/solver resolution; actuator injection; friction/material; reset velocity.
Regression artifactContact count/force trace, penetration limit, settle energy, slide angle, and visualized collision proxies.

Isolation order: geometry → mass/inertia → timestep/solver → actuator → friction → randomization. First replace a complex proxy with a known box or convex hull while holding material fixed.

D · Controller oscillates, saturates, or fails under payload
ObservationOvershoot, limit cycling, slow rise, steady-state error, load sensitivity, or unstable contact.
First invariantUnits, DOF mapping, single ownership, update rate, actuator limits/delay, and a contact-free plant are known.
Minimal testOne free-space joint step; log q, q̇, target, requested/applied effort, saturation, and controller update flag.
Ranked hypothesesWrong sign/mapping; rate mismatch; saturation; gain/plant mismatch; delay; payload inertia; contact coupling.
Regression artifactRise time, overshoot, settling, steady error, saturation fraction, and pass bands across payloads.

One-variable experiment: sweep only Kd with Kp, dt, control rate, payload, limits, and initial state frozen. A mode that changes both effort clamping and delay is not one-variable evidence.

E · Sensor or ROS 2 data is stale, shifted, missing, or unsafe
ObservationWrong image/depth, TF displacement, lost topics, time jump, incompatible QoS, or stale command.
First invariantInternal sensor is correct; bridge/domain/type/QoS, acquisition clock, frame/extrinsic, rate, and watchdog are explicit.
Minimal testKnown target → internal sample → published message → TF transform → consumer; compare the same acquisition ID.
Ranked hypothesesSensor model; coordinate convention; timestamp; bridge environment; QoS; TF direction; publish rate; consumer; timeout.
Regression artifactReference scene, raw sample/message pair, TF snapshot, QoS graph, latency distribution, watchdog test.
Set-Location C:\isaacsim
cmd /d /c "call setup_ros_env.bat && call python.bat standalone_examples\api\isaacsim.ros2.bridge\clock.py"

One-variable sequence: first change only the consumer to simulation time; then restore it and change only the extrinsic. Confirm the actual local topics—this example’s names are not proof of a standard /clock contract.

F · Simulation is slow, unstable at scale, or leaks memory
ObservationLow real-time factor, high tail latency, GPU idle, VRAM/RAM growth, or throughput collapse as environments/sensors grow.
First invariantWorkload, correctness gate, warm-up, simulated duration, wall duration, environment count, sensor/render settings are fixed.
Minimal testPhysics-only baseline; add one subsystem; scale geometrically; profile the first nonlinear knee.
Ranked hypothesesRendering/sensors; sync/readback; Python loop; reset/allocation; collision complexity; CPU bottleneck; memory pressure; logging.
Regression artifactRTF and step-latency percentiles, scaling curve, VRAM/RAM, profiler capture, and correctness comparison.
Set-Location C:\isaacsim
.\python.bat .\standalone_examples\benchmarks\benchmark_core_world.py --num-envs 1 --backend-type JSONFileMetrics
.\python.bat .\standalone_examples\benchmarks\benchmark_camera.py --num-cameras 1 --resolution 640 480 --num-frames 120 --backend-type JSONFileMetrics
nvidia-smi

One-variable experiment: disable rendering/sensor production for the same scenario and action trace. Exclude first asset fetch and shader compilation from steady-state timing. Physics and camera benchmark scripts are different workloads, so their direct difference does not prove camera cost.

Reproduction and evidence packet

Make every important failure hand-off ready

An asynchronous teammate should be able to reproduce, inspect, and challenge the conclusion without a screen-share. Store raw evidence separately from the explanation that interprets it.

1

Identity

failure_id, commit, dirty state, runtime/Kit/Python, OS, driver, GPU/CPU/RAM, command, environment, extension set.

2

Immutable inputs

Resolved config and hash, asset hashes, scenario ID, seed/RNG states, initial state, sampled parameters, data-split ID.

3

Native-rate traces

Requested/applied action, state, contact, controller tick, sensor acquisition/publish times, events, resource telemetry.

4

Failure boundary

First bad step, lowest failed invariant, expected/observed values, terminal code, screenshot/video, relevant log window.

5

Ranked hypotheses, predicted signatures, single changed variable, baseline/intervention/restoration/counter-test results.

Root cause and confidence, fix, regression test/threshold, residual limitations, owner, and link to raw artifacts.

Evidence rules

  1. Lead with observations; label interpretations and unknowns.
  2. Record the first divergence, not only the final crash.
  3. Compare like-for-like workloads with the same correctness gate.
  4. Keep nominal, fit, held-out, randomized, and cross-simulator results separate.
  5. Never call synthetic-only evaluation physical sim-to-real validation.
  6. A screenshot illustrates; a trace, manifest, and repeatable command support a claim.
Hiring signal: the simulator does not need to be failure-free. Show that every important failure becomes a bounded reproduction, a discriminating experiment, a measured fix, and a regression gate.
