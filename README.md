All learning pages share a book-style chapter rail generated by `book-layout.js`
and styled by `book-layout.css`.
- **Spine:** the `chapters` array in `book-layout.js` is the reading order. Chapter numbers and previous/next links are derived from it, so add a page there, never by renumbering.
- **Rail:** it expands the current page's outline and becomes a keyboard-accessible contents drawer on small screens.

## Isaac Sim lab chapters are generated

The ten Isaac Sim labs and their hub are written in Markdown (`robotics-simulation-engineer/*.md`). The matching `.html` pages are build output: edit the Markdown, then regenerate.

```powershell
python scripts/build_lab_pages.py
```

Lab commands assume the session variables `$Repo`, `$Launcher`, `$Assets`, and `$Run` from the hub's "Shared startup" section. Evidence goes into `runs\`, which is git-ignored.

## Checks

One command runs everything that CI runs before GitHub Pages deploys:

```powershell
python -m pip install -r requirements-learning.txt
python scripts/check_all.py
```

It covers:
- the lab-tool tests, including every planted fault;
- each exercise in both directions: with `LAB_IMPL=solution` the reference must pass, and the learner's file (starter or planted defect) must fail;
- the generated lab pages match their Markdown;
- internal links and anchors are valid, with case-sensitive paths as on Pages;
- every page is a chapter in the book spine;
- no machine-specific paths appear.

The ROS integration tests (real MCAP bags through the bag checker, and the watchdog node including `Ctrl+C`) run only inside the ROS environment:

```powershell
pwsh -NoProfile -File .\robotics-simulation-engineer\Start-IsaacRosJazzy.ps1 python -m unittest discover -s .\robotics-simulation-engineer\lab-assets\tests\ros -v
```

## Mirrored project pages

The CUDA kernel guide is mirrored from the private sibling checkout at
`..\Mercor_cuda\docs\index.html` into `cuda_kernel\index.html` because GitHub
Pages is not enabled for private repos on the current plan. The sync script also
accepts the legacy sibling name `..\cuda_kernel` or an explicit `-Source` path.

Sync it before committing guide updates:

```powershell
powershell -ExecutionPolicy Bypass -File .\scripts\sync-cuda-kernel-guide.ps1
```
